# 검증 기록

실제로 수행한 검증만 기록한다. 수행하지 않은 항목은 "미수행"으로 둔다.

## 1. 자동 테스트 (pytest) — 수행

- 일시: 2026-11-03, 로컬 (Python 3.11.9)
- 명령: `.venv/Scripts/python -m pytest -q`
- 결과: **65 passed**
- 범위: FastAPI 계층(인증·역할 검사·입력 검증·쿠키·CSRF·요청 제한)과 Supabase REST 요청 모양·오류 변환.
  실제 Supabase 대신 가짜 인증 서버와 RLS 규칙을 흉내 낸 메모리 저장소를 쓴다.
- 증명하지 못하는 것: 실제 PostgreSQL 의 RLS·컬럼 권한 → 2절.

주요 항목: 비로그인 401, 데모 로그인 HttpOnly 쿠키·본문에 토큰 없음, role 위조 422, 데모 버튼 값과 무관하게 DB 역할 적용,
작업자 타인 신고 조회 404, 작업자 PATCH/DELETE/초기화 403, 생성 시 status/action/due_date/reported_by/organization_id/role 지정 422,
다른 사업장 관리자 접근 404, 관리자 조치 → 작업자 조회 반영, 조치 없는 완료 400, 다른 출처 403, 비 JSON 415, 신고 요청 제한 429.

## 2. 실제 Supabase RLS·권한 검증 — 수행

- 일시: 2026-11-03, 실제 Supabase 프로젝트 + 로컬 서버(`http://127.0.0.1:8000`)
- 명령: `.venv/Scripts/python -m scripts.rls_check`
- 결과: **36 / 36 통과** (DB 직접 25건, 앱 API 11건) → 상세: [rls_check_result.md](rls_check_result.md)
- 데모 계정의 일반 사용자 토큰만 사용 (service_role 키 미사용). 검증용으로 만든 행은 실행 후 삭제.
- 확인한 것: 생성 시 상태·조치·기한·신고자·사업장 지정 거부, 작업자는 본인 신고만 조회, 작업자 수정·삭제·초기화 차단,
  역할 변경·프로필 생성 차단(작업자·관리자 모두), 조치 없는 완료 거부(CHECK), 완료일 자동 기록,
  관리자도 신고자·사업장 변경 불가, 관리자 변경이 작업자 조회에 반영.
- 미수행: 두 번째 작업자 계정(`RLS_TEST_WORKER2_*`)으로 작업자끼리 서로의 신고를 못 보는지 확인하는 항목.
  작업자가 타인(관리자)이 등록한 신고를 조회하지 못하는 것은 확인함.

## 3. 화면 확인 — 부분 수행

- 가짜 백엔드(1절과 같은 FakeAuth/FakeRepo)로 로컬 서버를 띄워 브라우저에서 확인:
  작업자 데모 로그인 → 본인 신고만 표시, 신고 등록 → 관리자 데모 로그인 → 현황 카드·조치 필요 목록·전체 목록 표시,
  조치 내용 없이 완료 처리 시 안내, 조치 입력 후 완료 처리 → 완료일 표시, 모바일(375px) 레이아웃. 콘솔 오류 없음.
- 실제 Supabase 연동 화면 확인 (로컬 서버, 2026-11-03): 작업자 데모 로그인 → 시연 신고 4건 표시,
  로그아웃 → 안전관리자 데모 로그인 → 현황(전체 4·접수 1·조치 중 2·완료 1·기한 경과 1)·조치 필요 목록·전체 표 표시.
  화면에서의 등록·수정 조작은 2절 앱 API 검증으로 대신했고, 배포 환경 화면 조작은 4절에서 확인한다.
